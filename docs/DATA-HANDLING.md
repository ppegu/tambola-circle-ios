# Tambola Circle data handling

This describes the implemented data flow; it is not a published store privacy policy.

Offline calls and settings are saved on the device. Existing preference synchronization remains compatible with the older guest/account service. Offline calling does not require a device phone number.

Online registration stores the device-selected Android or self-entered iPhone number, display name, consent timestamp, and a hash of a random device credential in Cloudflare D1. Native credentials are kept in native iOS Keychain / Android Keystore-backed encrypted storage. Phone numbers are labels shared with table members after explicit consent, not authentication credentials or verified phone ownership. iPhone numbers use a text field with country-code validation and mobile_source=manual_ios; Android uses mobile_source=device_selected. Both remain unverified. There is no SMS OTP or recovery code. No contacts, IMEI, advertising ID or location is requested. Microphone permission is requested only when the user taps unmute in table voice.

Native app launch and foreground create/update a device record before phone registration. The native credential store preserves a random app UUID alongside the independent random authentication credential. The locally cached metadata and D1 online_devices row contain that UUID, Android ANDROID_ID or iOS IDFV when available, platform, brand/manufacturer, model name/model identifier, OS name/version, app identifier/version/build, physical-device status, and server first/last-seen timestamps. Only allow-listed bounded fields are accepted. Failed startup synchronization retries while the app is active; offline calling remains available. Existing device credentials and profiles are preserved on upgrade. Registration associates player_id with the pre-existing device row. Device records are not broadcast to table members; the current user's UUID is visible in their account screen.

Platform identifiers are metadata, not proof of ownership and never account-access keys. They can change after platform resets or reinstall scenarios; no permanent hardware UUID is claimed. The native module reads Android Settings.Secure.ANDROID_ID or iOS UIDevice.identifierForVendor.

The table Durable Object stores round state, tickets, number calls, marks/unmarks, selected strips, readiness, claims, frozen evidence, automatic verification outcomes, schedules, membership and host actions in durable SQLite. Accepted events and round snapshots are projected to D1 with retries. Game events are retained as requested; no automatic short event-history expiry is configured. Expired single-use WebSocket connection tickets are cleaned up daily.

Current table members can view names, selected numbers, ready tickets and live marks. Unconfirmed ticket candidates are private to their owner. History responses and archived D1 round snapshots omit mobile numbers. Removed members lose table snapshot, command and socket access. Shared links can be revoked by the host; the six-digit table code remains usable by the circle.

The server stores only a hash of each device authentication secret and each one-use socket ticket. Short socket tickets expire after 60 seconds and can be consumed once. Socket sessions refresh after 12 hours. General request-failure logs omit credentials, request bodies and phone numbers.

Reinstalling or changing devices does not restore the device identity through its phone number. The new flow does not currently include account migration or recovery. iPhone uses the user-authorized manual number flow. Unsupported Android selection remains unavailable for new online registration. There is no web app.

Coin wallets, immutable ledger entries and round reservations are stored in D1. Test-purchase IDs deduplicate retries. No card, bank or payment-provider information is collected; test packs are free. Historical proof/vote records from older versions remain readable but new rounds use automatic verification.

Table voice uses managed Cloudflare Realtime SFU and TURN. Mic defaults muted; authorized current-table members can listen without requesting microphone capture. Tapping unmute requests OS permission and publishes live audio to listeners at that table. The app does not record, transcribe or retain audio. Cloudflare processes live media and transport metadata; transport encryption terminates at the SFU, not only on participants' phones. SDP passes through the authenticated Worker but is not persisted or application-logged. The voice Durable Object stores table/player IDs, opaque client/session/track IDs, readiness and renewable lease deadlines. Departed, expired and removed sessions are retired and cleaned up with retry; provider identifiers remain until cleanup succeeds. Native capture closes on mute, leave, background, table disconnect and audio interruption. Incoming speaker mute also masks caller announcements without changing saved volume. Provider infrastructure logs and shared-account billing follow Cloudflare settings.
